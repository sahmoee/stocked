# Security policy

## Reporting a vulnerability

Do not file public GitHub issues for vulnerabilities, exposed credentials, authentication bypasses, private user data, or screenshots containing personal information.

Report the issue privately through [GitHub private vulnerability reporting](https://github.com/sahmoee/stocked/security/advisories/new) when it is enabled. If that option is unavailable, contact the repository owner through the verified GitHub profile and include only the minimum information needed to establish a private channel.

## Include

- Affected application, version, and build
- A concise impact description
- Reproduction conditions
- Relevant endpoint or component
- Suggested mitigation, if known

Never include live secrets, full access tokens, private keys, personal journals, media credentials, or production data.

## Supported version

Security fixes target the current default branch and the most recently distributed application build. Rotate any credential suspected of exposure; deleting it from Git history is not sufficient.
