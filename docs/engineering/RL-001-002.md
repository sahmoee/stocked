# RL-001 / RL-002 — Pause & Resume Active Cooking, Cancel Without Completion

## New file

### `Stocked/CookSessionPersistence.swift`
- `ActiveCookSessionStatus` — `active / paused / completed / canceled` (nonisolated, Codable, Sendable).
- `CookSessionTimerState` — per-step timer with wall-clock semantics: running timers persist a fire **date** (`endDate`), paused timers a frozen `pausedRemaining`, plus `isFinished`. A timer whose fire date passed while the app was closed/locked restores as finished.
- `ActiveCookSessionSnapshot` — full Codable session record: recipe id/title, ingredients, steps, current step, completed steps, checked ingredients, servings, session substitutions, selected appliances/components, notes, timers, plannedMealID, startedAt/pausedAt/lastSavedAt, status, and a `completionToken` UUID. Carries the recipe payload so resume rebuilds the cooking screen directly (never via the recipe detail page).
- `ActiveCookSessionStore` (`@MainActor @Observable` singleton) — persists to UserDefaults with **immediate write-through on every mutation** (survives force-close, relaunch, backgrounding, offline). API: `save`, `pause`, `pauseCurrentIfActive` (safety net), `adoptResumed`, `cancel`, `clearIfStale`, `clearFinished`, `resumable`, and the idempotent completion guards:
  - `markCompleted(token:) -> Bool` — deduction gate; token ledger persisted, so repeated Finish taps / resume-after-complete / relaunch can never deduct twice.
  - `markMealRecorded(token:) -> Bool` — separate gate for meal history / streaks / leftovers.
  - `cancel()` consumes **both** token sides so a zombie Finish screen can't complete a canceled session. Never touches planned meals.
- `CookSessionResumeCard` — the shared paused-session banner (charcoal/gold, serif, matches DesignSystem) with Resume + Cancel Meal actions. This card plus `ActiveCookSessionStore.shared.resumable` is the lightweight model Home/Daily Brief could also render.

## Changed files

### `Stocked/CookingFlow.swift` (CookingFlashcardView + TimeToPlatView + RatingView)
- `CookingFlashcardView` gains an optional `resume: ActiveCookSessionSnapshot?` (defaulted — all existing call sites unchanged) that restores completed steps, checked ingredients, current step, and timers (wall-clock adjusted) on appear.
- Session record bootstrap on appear: adopt an explicit resume, silently pick the same cook back up after a force-close / floating-pill re-entry, or start a fresh record.
- Write-through capture on step change, card change, ingredient check, timer change (engine callback), and scene-phase transitions (backgrounding/lock).
- Back-chevron intercept via a scoped `.environment(\.stockedDismiss, …)` on the shell only (pushed destinations keep standard back behavior): presents the 3-action dialog — **Pause Cooking / Cancel Meal / Continue Cooking**. An untouched cook leaves quietly without nagging.
- Pause: freezes the snapshot, suspends in-app countdown tasks **while keeping pending timer notifications** (a pot on the stove still alerts on a locked phone), keeps the floating pill alive.
- Cancel: confirmation alert explains progress is discarded and the meal is NOT recorded; clears record/timers/step progress/CookNowSession context, consumes tokens, pops to the hub via `.stockedPopToRoot`. Planned meals are untouched; restarting the recipe opens a clean session.
- `.onDisappear` safety net converts any bypassed exit into a paused record.
- `TimeToPlatView` deduction sheet: "Deduct from Pantry" now runs only when `completeCurrentSession()` consumes the token — inventory deducted exactly once per session id. "Skip" marks the session completed (never resumable again) without consuming the deduction token.
- `RatingView.finishMeal()`: guarded by `recordMealForCurrentSession()` so past-meal record, streaks, HealthKit log, planned-meal cook flag, and leftovers are recorded exactly once; clears the finished record afterward.

### `Stocked/StepTimerEngine.swift`
- `StepTimer` gains a restore initializer (`remaining` / `isFinished`).
- Engine: `exportStates()` (running → fire date, paused → frozen remaining), `restore(_:)` (wall-clock adjustment, finished-while-away → done, notification re-schedule, Live Activity for the soonest running timer), `suspendKeepingNotifications()` (pause-and-leave without killing local notifications), `onStateChange` hook so the cook flow snapshots on every timer mutation, and resuming a paused countdown now re-schedules its notification.

### `Stocked/CookHubView.swift` (CookHubView + CookNowHomeView)
- Both the Cook tab entry and the Cook Now hub show `CookSessionResumeCard` when `ActiveCookSessionStore.shared.resumable` exists (distinguishing paused vs in-progress; completed/canceled/stale never appear — `clearIfStale()` runs on hub appear).
- Resume pushes `CookingFlashcardView` directly at the exact saved step with the saved servings/substitutions.
- Cancel-from-card uses the same RL-002 confirmation copy (no deduction, no history, plan preserved).
- `goResumeCook` added to the `.stockedPopToRoot` collapse list.

## Invariants honored
- Inventory is never mutated on start/pause/background/close/resume — only via the single token-guarded deduction call (`GuestDataStore.deductIngredients(weighted:)`, called through the existing public API only).
- No pbxproj edits, no new dependencies, no force-unwraps, Swift 6 default main-actor isolation respected (new value types are `nonisolated` + `Sendable`; store is `@MainActor @Observable`).
- GuestDataStore and all non-owned files untouched.

## Caveats
- The pre-existing modifier misplacement in `CookingFlashcardView` (several `.onAppear`/`.alert`/`.fullScreenCover` chained onto `TimeToPlatView` inside its `navigationDestination`) was left as-is to keep the diff surgical; the new RL-001/002 modifiers are attached at the correct (flashcard) level and do not depend on the misplaced ones.
- Session "notes" field exists in the snapshot for the spec/API but the flashcard flow has no notes UI to populate it yet.
- Exactly one session is tracked at a time (matching the app's single-active-session model); starting a different recipe replaces a prior paused record.
