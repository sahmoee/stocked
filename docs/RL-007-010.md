# RL-007 + RL-010 — Purchase Dedup & Multi-Store Grocery

## New files (Stocked/)
- **PurchaseDedupEngine.swift** — pure `nonisolated` engine. DTOs: `PurchaseImportSource`, `PurchaseImportRecord` (persisted history line), `PurchaseImportCandidate`, `PurchaseDupFlag`, `PurchaseDupResolution` (merge / keepBoth / skip). `evaluate(candidates:history:transactionKey:now:window:)` flags likely duplicates in a 12h window using same-store + normalized name (FoodNameMatcher/SearchNormalization), barcode when present, transaction-key identity, and a package-size veto (UnitMath) so a 32 oz vs 12 oz isn't flagged. `transactionKey(store:date:itemNames:)` = stable FNV-1a receipt/trip key.
- **PurchaseDedupLog.swift** — `@Observable PurchaseImportLog` (LocalDatabase key `purchaseImportLog_v1`): cap 200 entries, prune >7 days. Owns the shopping-trip id (`currentTripID()`, reused within 6h so multi-store segments share one trip; `storeSegments(forTrip:)` lists a trip's stores).
- **PurchaseDedupReviewView.swift** — flagged-duplicate review sheet (`PurchaseDupReviewContext` + `PurchaseDedupReviewView`): evidence in plain language, per-item Skip (default) / Merge / Keep Both chips, unflagged items summarized, commit hands resolutions back to the caller. Also `PurchaseImportMerge.refreshExisting` — the one Merge implementation: refresh existing row's price/store/brand/size/expiry + confirm, no quantity bump.
- **MultiStoreAssignments.swift** — `@Observable` side-table `groceryItemID → store` (LocalDatabase key `multiStoreAssignments_v1`); resolution = explicit assignment → `GuestDataStore.itemStoreHistory` (learned) → `session.preferredStore`; pruned when rows leave the list. Models.swift untouched.
- **MultiStoreViews.swift** — `MultiStoreCatalog` (shared store roster + learned extras), `MultiStorePickerMenu` (row store submenu), `MultiStoreSegmentFooter` (per-store "move purchased → Pantry" button with completion state).

## Changed files
- **ReceiptScannerView.swift** — `addItemsToPantry()` now computes a receipt transaction key, runs `PurchaseDedupEngine.evaluate` against `PurchaseImportLog`, and presents the review sheet when flagged (new `.sheet(item: $dupReview)`); commit moved to `commitItemsToPantry(resolutions:)`: skip → never enters inventory, merge → metadata refresh only, otherwise unchanged import path + logs a `PurchaseImportRecord` per accepted line and teaches `itemStoreHistory` (name → detected store).
- **GroceryListView.swift** — RL-007: "Move Checked → Pantry" and the new per-store footers route through `beginPantryTransfer` → engine → optional review (new `GrocerySheet.purchaseReview` case) → `commitPantryTransfer`, which stamps each line with the shared trip id + store segment and logs to `PurchaseImportLog`. RL-010: `@AppStorage groceryGroupByStore_v1` toggle in the Sort menu ("Group by Store", unified view stays default), store-grouped sections in `rebuildSections` (default store first), row context-menu "Store:" submenu to move items without recreating them, per-store segment footers in the Bought view with completion state, loop message notes multi-store segments.

## Caveats
- Barcode and one-off manual adds aren't wired into the dedupe check (BarcodeScannerView/GuestDataStore are owned by other agents); the engine + log accept `.barcode`/`.manual` sources, so wiring is a small follow-up in those call sites.
- Trip continuation window is 6h (engine dedupe window 12h); both are constants.
- Skipped/merged grocery rows still leave the list on transfer (they were bought — keeping them would re-flag next trip).
- No Swift toolchain in this environment: files brace/paren-checked and API-verified against the codebase, but not compiled.
